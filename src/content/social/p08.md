My AI agents have shift changes. It sounds silly. It fixed the most annoying problem I had.

The problem: a new session starts with no memory. It re-reads half the repo to work out where things stand, then confidently trusts a TODO comment from three weeks ago.

So there are two protocols, written as skills.

End of shift:
Clean the repo. No stray branches, no half-staged files.
Verify what actually works. Run it. Don't infer it from the code.
Sync the docs to reality.
Leave a written health report the next engineer, human or agent, can act on without this conversation.

Start of shift:
Rebuild context from the repository alone.
Check the handover's claims against reality, not the other way round.
Surface what moved since: merges, new issues, failed CI.
Recommend the first task.

The rule that makes it work: the repo is the memory. Not the chat. If it isn't committed or written down in the repo, the next shift doesn't know it.

A hook also re-injects the current repo, branch and PR state when a session resumes, so agents don't burn turns re-orienting.
