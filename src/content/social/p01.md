I told my AI agents, in writing, never to commit in the shared checkout.

Several of them work against the same repos at once, and the shared checkout can hold another agent's uncommitted work at any moment. One stray commit there sweeps it into the wrong branch.

The fix wasn't a better sentence. It was a hook that blocks the command. Now an agent that tries gets a BLOCKED message and a pointer to take its own git worktree.

Rules a model is supposed to remember are suggestions. Rules the harness enforces are rules.
